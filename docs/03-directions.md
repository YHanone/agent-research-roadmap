# Agent 研究方向分析

研究门槛按本科生第一次独立项目估计：低、中、高。它同时考虑概念难度、实验成本和结论是否容易混淆。

## Planning：任务规划与推理

- **核心问题：** 如何把长任务拆成可执行步骤，并在环境反馈后修正计划。
- **主流方案：** chain/tree search、planner-executor、ReAct、world model、verifier-guided search。
- **未解决问题：** 计划经常只是语言上合理；执行时失效；搜索成本高；长任务误差累积。
- **可研究点：** 何时重规划、计划粒度、预算自适应、计划与执行一致性指标、失败预测。
- **门槛：** 中高。
- **复现入门：** 适合，但应使用可自动验证的任务，并与相同 token 预算下的直接方法比较。

## Memory：记忆与长期经验

- **核心问题：** 保存什么、何时检索、如何更新和遗忘，记忆能否改善未来决策。
- **主流方案：** 上下文窗口、摘要、向量检索、episodic/semantic memory、反思后写入、层级存储。
- **未解决问题：** 噪声和过时记忆污染；检索相似不等于有用；评测周期短；收益可能只是更多 token。
- **可研究点：** 写入价值预测、冲突处理、遗忘策略、负迁移检测、固定上下文预算比较。
- **门槛：** 中。
- **复现入门：** 很适合，尤其可在 Coding Agent 中研究历史错误经验是否帮助新任务。

## Tool Use：工具调用

- **核心问题：** Agent 如何选择工具、生成参数、解释观察并从调用失败中恢复。
- **主流方案：** function calling、ReAct、工具检索、工具使用微调、执行反馈与重试。
- **未解决问题：** schema 变化、参数幻觉、错误恢复、工具组合、权限和安全。
- **可研究点：** 工具失败诊断、工具选择校准、最少调用策略、未知工具泛化、异常注入评测。
- **门槛：** 中。
- **复现入门：** 很适合；本地确定性工具即可完成低成本实验。

## Multi-Agent：多智能体协作

- **核心问题：** 多个 Agent 如何分工、通信、验证和达成一致。
- **主流方案：** 固定角色、辩论、层级管理、共享黑板、市场/投票机制。
- **未解决问题：** 通信冗余、错误放大、角色同质化、成本高，以及无法证明收益来自“协作”而非更多采样。
- **可研究点：** 公平预算、动态角色、通信压缩、冲突诊断、单 Agent 强 baseline。
- **门槛：** 高。
- **复现入门：** 可以阅读和小规模复现，但不建议作为第一个独立选题。

## Reflection：反思与自我改进

- **核心问题：** Agent 能否利用结果、测试或语言反馈改变后续策略。
- **主流方案：** self-critique、verbal feedback、生成-评价-修订、外部 verifier、经验写入。
- **未解决问题：** 自我评价不可靠；反思可能只增加采样；错误意见会被强化；停止条件不清晰。
- **可研究点：** 何时反思、可信反馈源、反思有效性预测、反思与重新采样的公平比较。
- **门槛：** 中。
- **复现入门：** 适合，但必须加入“相同调用次数下重新生成”基线。

## RAG Agent：检索增强型 Agent

- **核心问题：** Agent 如何主动决定何时检索、检索什么，并把证据用于多步行动。
- **主流方案：** query rewriting、多跳检索、reranking、引用验证、agentic RAG。
- **未解决问题：** 错误传播、证据冲突、延迟成本、检索时机、引用看似正确但不支持结论。
- **可研究点：** 检索停止策略、冲突证据处理、预算分配、工具与文档联合选择。
- **门槛：** 中低到中。
- **复现入门：** 很适合，但要和普通 RAG 区分，研究决策过程而不只是替换检索器。

## Coding Agent：代码智能体

- **核心问题：** Agent 如何定位代码、规划修改、执行测试、诊断失败并迭代修复。
- **主流方案：** repository search、编辑器/终端接口、测试反馈、patch generation、planner/verifier、检索增强。
- **未解决问题：** 仓库级上下文、测试过拟合、长轨迹错误恢复、成本、隐藏测试泛化、环境复现。
- **可研究点：** 失败类型驱动的修复、测试选择、停止策略、上下文压缩、预算分配、历史经验迁移。
- **门槛：** 中；完整 SWE-bench 为中高。
- **复现入门：** 最推荐。先从小型任务或 SWE-bench 子集开始，不要一开始跑完整榜单。

## GUI Agent：图形界面智能体

- **核心问题：** Agent 如何理解屏幕、定位控件并在动态界面执行长序列操作。
- **主流方案：** 多模态模型、accessibility tree、截图 grounding、动作轨迹微调、层级规划。
- **未解决问题：** 分辨率和界面变化、不可逆动作、安全、延迟、真实环境复现。
- **可研究点：** 失败恢复、视觉/结构信息融合、权限确认、跨应用泛化、可逆性评测。
- **门槛：** 高。
- **复现入门：** 可复现 benchmark 的小子集，但环境配置和调用成本较高。

## Agent Evaluation：智能体评估

- **核心问题：** 如何可靠测量任务完成、过程质量、成本、稳定性和安全性。
- **主流方案：** 可执行任务、环境状态检查、人工/模型裁判、轨迹分析、成功率与成本指标。
- **未解决问题：** 数据泄漏、裁判偏差、环境不稳定、指标只看最终结果、不同预算不公平。
- **可研究点：** 过程指标、失败分类、可重复性、扰动测试、预算归一化、污染检测。
- **门槛：** 中低到中。
- **复现入门：** 强烈推荐；低算力但要求严谨，适合形成第一项可靠研究。

## Agent Safety：智能体安全

- **核心问题：** 在能调用工具、访问数据和执行动作时，如何限制有害或越权行为。
- **主流方案：** sandbox、最小权限、policy checker、人类确认、监控、红队评测。
- **未解决问题：** prompt injection、间接注入、工具链放大、数据外泄、长期目标漂移。
- **可研究点：** 权限边界评测、异常行为检测、可逆执行、攻击链基准、效用与安全权衡。
- **门槛：** 中高；真实系统风险高。
- **复现入门：** 适合在隔离环境做评测，不适合初期直接接触真实账号和敏感工具。

## 推荐顺序

1. **Coding Agent**：与既有背景最匹配，自动测试提供客观反馈。
2. **Agent Evaluation**：成本低，能培养论文最看重的证据质量。
3. **Coding Agent Memory**：把 Memory 收敛到具体任务，避免做成普通向量检索项目。

建议的组合选题不是“做三个方向”，而是以 Coding Agent 为任务场景、Evaluation 为研究方法、Memory 或错误恢复为一个待检验机制。
