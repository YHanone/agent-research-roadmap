# 算力、API 与低成本策略

## 分阶段需求

| 阶段 | 最低资源 | 推荐资源 | 不需要做的事 |
|---|---|---|---|
| 第 1-2 月 | 普通 CPU、8GB 内存 | 免费 Colab/Kaggle | 购买 GPU、训练大模型 |
| 第 3-4 月 | CPU 可完成小模型；免费 GPU 更快 | 8-16GB VRAM | 预训练真实 LLM |
| 第 5-6 月 | 少量 API 或 7B/8B 量化模型 | 学校 16-24GB GPU | 追求完整 benchmark |
| 第 7-9 月 | 复现任务决定；Docker 空间较重要 | 学校服务器、受控 API 预算 | 未 pilot 就批量运行 |
| 第 10-12 月 | 多次重复实验 | 1-2 张 24GB GPU 或 API 配额 | 用昂贵模型掩盖方法问题 |

Coding Agent 的瓶颈经常是容器、磁盘、并发和 API 成本，不只是 GPU。申请学校资源时应说明：GPU 型号/显存、CPU 核数、内存、磁盘、Docker 权限、外网访问和最长任务时间。

## API 预算控制

- 每次运行记录输入/输出 token、调用次数、模型和价格版本。
- 先运行 1-3 个 smoke test，再运行 10-20 个 pilot。
- 设定每任务最大调用数、token 和 wall-clock time。
- 缓存确定性工具结果，但不要在不同实验条件间错误复用模型输出。
- 开发阶段用便宜模型验证流程，正式比较时固定模型版本。
- 至少保存失败任务的完整可审计轨迹。

## 开源模型策略

- 前期学习不要求本地运行大模型。
- 单卡 16-24GB 可考虑量化 7B/8B 模型用于机制实验，但性能不能代表闭源强模型。
- 不把“开源模型效果较差”直接归因于 Agent 方法。
- 本地模型和 API 模型的 tokenizer、上下文和 function calling 行为不同，应分开报告。

## 学校资源申请清单

申请前准备一页说明：

1. 研究问题与任务规模。
2. 预计模型、样本数、重复次数和单任务耗时。
3. 需要的 GPU/CPU/内存/磁盘。
4. 预计总 GPU 小时和 API 费用。
5. 数据许可、隐私和安全措施。
6. 先导实验结果，证明资源不会被用于盲目搜索。

## 资源升级触发条件

只有满足以下条件才增加算力：

- smoke test 和 pilot 已稳定。
- 评测脚本已经人工抽查。
- 研究假设和停止条件已经写明。
- 预计成本表已经完成。
- 扩大规模会增加证据强度，而不只是得到更漂亮的数字。
